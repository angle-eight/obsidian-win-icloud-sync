# ObsidianWinSync 次期実装計画

## 1. 次期リリースの目標

動作確認済みのコンソール版を、日常的に常駐利用できる Windows アプリへ発展させる。

次期リリースの完了条件は次のとおり。

- Windows のタスクトレイに常駐し、30秒間隔をデフォルトとして自動同期できる
- タスクトレイから同期開始、一時停止、再開、設定、ログ表示、終了を操作できる
- 同期成功、競合、エラーを Windows 通知で確認できる
- 誤操作や障害に備え、上書き・削除前のファイルを一定期間復元できる
- コンソール版と常駐版が同じ同期ロジックを利用する
- 単一実行ファイルまたは分かりやすいインストーラーで配布できる

## 2. 対象範囲

### 含めるもの

- 同期コアのライブラリ分離
- ファイルログとログローテーション
- 上書き・削除前のバックアップ
- Windows タスクトレイ常駐アプリ
- 設定編集画面
- 競合一覧と競合解決画面
- Windows 通知
- Windows ログイン時の自動起動設定
- 配布用 Release ビルド

### 今回は含めないもの

- ファイル内容の自動マージ
- 複数 Vault の同時管理
- クラウドAPIや独自同期サーバー
- macOS / Linux 対応
- FileSystemWatcher だけに依存する即時同期

定期フルスキャンを正とし、FileSystemWatcher は将来の高速化候補に留める。

## 3. アーキテクチャ変更

ソリューションを次の構成へ整理する。

```text
ObsidianWinSync.Core/          設定、スキャン、同期計画、実行、状態管理
ObsidianWinSync.Cli/           現在のコンソール操作
ObsidianWinSync.Tray/          Windows タスクトレイと設定画面
ObsidianWinSync.Tests/         同期コアの単体・統合テスト
ObsidianWinSync.Tray.Tests/    UIから分離した常駐制御ロジックのテスト
```

UI はファイルを直接操作せず、`SyncCoordinator` を通して同期を開始する。CLI と Tray が同じ `SyncCoordinator` を使うことで、同期結果の差を防ぐ。

`SyncCoordinator` は以下を返す。

- 開始・終了時刻
- コピー、削除、競合、スキップの件数
- ファイルごとの結果
- 警告とエラー
- 次回同期予定時刻

## 4. 安全性の強化

### バックアップ

上書きまたは削除前の対象を、状態フォルダ配下のバックアップ領域へ退避する。

```text
.obsidian-win-sync/
├─ state.json
├─ logs/
└─ backup/
   └─ 2026-07-22T063000Z/
      ├─ local/...
      └─ icloud/...
```

- デフォルト保持期間は7日
- 設定JSONで保持日数とバックアップ有効/無効を指定可能
- バックアップ成功後にだけ上書き・削除する
- 容量上限を超えた場合は同期を止めず、警告とともに古い世代から削除する
- UI と CLI の両方からバックアップ一覧と復元手順を確認できるようにする

### 状態ファイル

- 読み込み不能時に自動で空状態へ戻さず、同期を停止する
- 更新前の `state.json.bak` を1世代保持する
- Vault パスの組み合わせを状態ファイルに記録し、別の Vault への誤適用を防ぐ
- アプリ更新に備えてスキーマバージョンと移行処理を用意する

### ログ

- コンソール表示とは別に日単位のファイルログを保存する
- Vault 外の状態フォルダを推奨し、ノート本文はログに残さない
- 通常ログには操作、相対パス、結果、所要時間を記録する
- デフォルト保持期間は14日
- UI からログフォルダを開けるようにする

## 5. タスクトレイ仕様

### 状態

- `同期済み`: 通常アイコン
- `同期中`: アニメーションまたは状態表示
- `一時停止`: 一時停止アイコン
- `競合あり`: 警告アイコン
- `エラー`: エラーアイコン

### メニュー

- 今すぐ同期
- 同期を一時停止 / 再開
- 競合を確認
- 最後の同期結果
- 設定
- ログを開く
- Windows ログイン時に起動
- 終了

### 通知

- 通常の同期成功は通知せず、設定で有効化可能とする
- 競合、連続失敗、設定エラーは通知する
- 同じエラーを短時間に繰り返し通知しない
- 通知をクリックすると対象画面またはログを開く

### 二重起動

名前付き Mutex で常駐アプリを1プロセスに制限する。2回目の起動は既存プロセスへ設定画面表示を依頼して終了する。

## 6. 設定JSONの拡張案

既存設定との後方互換性を保ちながら、次を追加する。

```json
{
  "localVaultPath": "C:\\path\\to\\local-vault",
  "icloudVaultPath": "C:\\path\\to\\icloud-vault",
  "intervalSeconds": 30,
  "excludePatterns": [".obsidian/workspace*.json", "*.tmp"],
  "stateFilePath": "state.json",
  "backup": {
    "enabled": true,
    "retentionDays": 7,
    "maximumSizeMb": 1024
  },
  "logging": {
    "retentionDays": 14,
    "minimumLevel": "Information"
  },
  "notifications": {
    "notifyOnSuccess": false,
    "notifyOnConflict": true,
    "notifyOnError": true
  },
  "startWithWindows": false
}
```

未知の設定項目は無視し、既存ファイルをそのまま読み込めることを受け入れ条件とする。

## 7. 実装フェーズ

### Phase 1: 同期コアの分離

- `Core`、`Cli`、`Tray` のプロジェクトを作成する
- 現在の同期ロジックを挙動を変えずに `Core` へ移す
- `Application` に集中している処理を `SyncCoordinator` へ移す
- コンソール入出力をインターフェース化する
- 既存17テストを維持し、CLI の回帰テストを追加する

完了条件: CLI のコマンドと終了コードが現状から変わらず、全テストが成功する。

### Phase 2: ログと実行結果モデル

- 構造化された同期結果モデルを追加する
- ファイルログ、保持期間、ログローテーションを実装する
- エラー種別を設定、競合、一時的I/O、致命的I/Oに分類する
- 同期件数と所要時間をCLIにも表示する

完了条件: 成功、競合、部分失敗の結果をUIに依存せず取得でき、ログから処理を追跡できる。

### Phase 3: バックアップと復元

- 上書き・削除前のバックアップを実装する
- 保持期間と容量上限によるクリーンアップを実装する
- `backup list` と `backup restore` CLI コマンドを追加する
- 復元先に変更がある場合は上書き確認を必須にする

完了条件: 更新・削除したファイルをバックアップから復元でき、バックアップ失敗時に元ファイルを変更しない。

### Phase 4: タスクトレイ基本機能

- Windows Forms の `NotifyIcon` を使用して常駐アプリを作る
- 状態アイコン、メニュー、今すぐ同期、一時停止、終了を実装する
- 名前付き Mutex で二重起動を防ぐ
- 終了時は進行中の同期を安全な境界まで待つ

完了条件: 8時間の連続運転で多重同期やハンドルリークがなく、停止・再開・終了が正しく動作する。

### Phase 5: 設定と競合画面

- Vault 選択、同期間隔、除外、バックアップ、通知を編集できる画面を作る
- 保存前に設定を検証し、問題箇所を画面内に表示する
- 競合一覧、テキスト差分、local / iCloud / skip 選択を実装する
- 設定変更後は安全に同期スケジュールを再構成する

完了条件: JSONを直接編集せずに初期設定と競合解決ができ、既存JSONとの往復で設定を失わない。

### Phase 6: 通知と自動起動

- Windows 通知を競合・エラーへ接続する
- 通知抑制と連続失敗の集約を実装する
- Windows ログイン時の自動起動をユーザー操作で切り替えられるようにする
- 自動起動後にウィンドウを出さずタスクトレイへ常駐する

完了条件: 再ログイン後に設定どおり起動し、通知から競合またはエラーを確認できる。

### Phase 7: 配布と受け入れ試験

- win-x64 の self-contained Release を作成する
- 単一ファイル配布とインストーラー方式を比較し、更新しやすい方式を採用する
- バージョン表示、ライセンス、アンインストール手順を整備する
- 実際の iCloud Drive と Obsidian 起動中の状態で受け入れ試験を行う

完了条件: .NET SDKのないWindows環境で導入、常駐、自動起動、更新、削除が行える。

## 9. 重点テスト

- アプリ終了直前、スリープ復帰直後、ネットワーク不安定時の同期
- iCloudの未ダウンロードファイル、読み取り専用、ロック中ファイル
- Obsidianがファイルを連続更新している最中の同期
- バックアップ容量上限、ディスク不足、状態ファイル破損
- タスクトレイからの連打、同期中の一時停止・終了
- Windowsログイン時の自動起動と二重起動
- 日本語、絵文字、長いパス、大容量添付ファイル
- 旧設定JSONと旧状態ファイルからの移行

## 10. 次期リリース後の候補

- FileSystemWatcherを補助的に使った低遅延同期
- 三方向マージと競合コピー作成
- 複数Vault管理
- 同期履歴画面と一括ロールバック
- 自動アップデート
